* Feature **#6092** : Processor tasks are no longer set to `Failed` and left. A task whose node is stopped, or cannot renew its heartbeat, is put back to be run again. A task that hits a fault, which now includes being unable to write its error stream, is set to `Retry` and tried again after `stroom.processor.taskRetryDelay` (10 minutes) until it has hit `stroom.processor.maxTaskFaults` (3) faults, when it is set to `Aborted`. Faults that have nothing to do with the stream, e.g. the run as user being disabled, are not counted. A task terminated by a user is set to `Aborted`. A run that is put back, hits a fault or is terminated deletes the output streams it wrote, apart from its error stream if the task is set to `Retry` or `Aborted`, unless it hit the last fault. Output left by earlier runs of a task is deleted before it is run again. Output that a task makes out of date is now only deleted once the task is `Complete`, and includes that of `Aborted` tasks. A run whose task is taken from it is terminated within a minute. Tasks are no longer left queued for ever: a node that is stopping puts back the tasks it has been given, a master node puts back its queue when it stops, `Processor Task Manager Release Old Queued Tasks` puts back the tasks a node handed out as master that were not started, even if it is no longer the master, and `Processor Task Reaper` puts back tasks left queued by a node that is not active. Aborted tasks are kept for `stroom.processor.abortedTaskDeleteAge` (30 days). Existing `Failed` tasks become `Aborted` on upgrade and are then deleted at that age, unless `stroom.processor.deleteAge` is zero, which turns off all deletion. All nodes must be stopped to upgrade.
